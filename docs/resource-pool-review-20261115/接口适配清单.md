# 资源平台与调度执行平台接口适配清单

日期：2026年11月15日。所有“建议”字段和路由均未实现、未由双方冻结。对照基线见评估报告。

## 1. 身份与状态

| 对方字段/语义 | 己方字段/语义 | 建议映射与约束 |
|---|---|---|
| node_id，UUID | nodes.id，thor1/2/3 | 新增显式bindings；不改既有任务历史中的node_id |
| device_fingerprint | 既有板卡身份核查记录 | 只用于核对与绑定，原始设备标识不进入网页/日志；同一实体的UUID恢复必须可追踪 |
| cluster_id，管理目录归属 | Kube.cluster，实际kubeconfig执行集群 | 分开保存resource_cluster_id与execution_cluster_id，确认后关联；目录分组不等于K3s集群 |
| hostname/IP | kube_node、node_uid | 用途不同；保存现有K3s UID和绑定验证版本，节点重建后核对，禁止仅按同名自动覆盖 |
| registration_status / authorization_status / pool_membership / scheduling_enabled | enabled / healthy / scheduler过滤原因 | 审批通过、在池、允许分配、采集新鲜、K3s Ready、应用兼容共同决定新分配资格 |
| operational_status与last_resource_at | observed / snapshot / error | 同时保留sampled_at、received_at、heartbeat_at和质量信息；查询时间不能替代采样时间 |
| architecture=aarch64 / arm64 | Kubernetes/image使用arm64 | 对方候选支持别名，己方部分约束为精确比较；适配层统一规范值并保留原值 |
| labels | tags及应用能力 | 管理标签与模型/运行时能力分开保存，合并时不覆盖执行能力，也不凭标签宣布模型可运行 |
| runtime_status=ONLINE | 会话READY/RUNNING | 节点在线与容器就绪分开，不互相映射 |

bindings建议至少记录：物理UUID、业务节点ID、资源目录集群、执行集群、Kubernetes节点名/UID、核验依据、验证时间、状态和版本。三板UUID尚未真实采集绑定，本轮不预填。

## 2. 单位、容量与网络

| 输入 | 转换/处理 |
|---|---|
| memory.available_bytes | 内部优先保留整数bytes；对现有memory_mb采用向下取整bytes/2^20，页面标MiB |
| memory_gb / vram_total_gb | 对方实现除以2^30，实为GiB；不能按十进制GB处理；其候选值已四舍五入两位，不宜作为临界准入的唯一原始量 |
| available_capacity.memory_total_gb | 目录总量减执行投影占用，不能直接当作实时MemAvailable |
| GPU count | 与K3s设备声明和实际模型兼容性分别核对；采集显存未知不等于没有可执行GPU |
| Thor共享内存 | CPU/GPU预算在统一物理内存中协调，不把系统内存和所谓GPU显存简单求和；先确认实际采集接口 |
| link_speed_mbps | 仅标称链路速率；不映射为有效任务传输带宽 |
| tx/rx_rate_bytes_per_second | 接口实际流量；不等于剩余可用带宽 |
| 自己的分片下载观测 | 保留已有时间戳、过期与来源语义；有明确端到端探测后再补外部bandwidth_mbps |
| LINK_UP | 不是视频输入、回调或仓库可达的证明，分别验证 |

新会话判断预算、运行时余量及待启动承诺；已有自有会话复用不再申请相同内存/GPU。运行时已用内存与逻辑承诺存在重合，避免直接把二者重复相减。公式须用真实采样和并发场景验证后再冻结。

## 3. API能力差异与改动入口

对方SINGLE_NODE/DISTRIBUTED与己方task_session不是同一维度。当前视频应用在每个节点加载完整模型并运行完整分片；先按每节点约束选出可执行资源，再由己方调度片段，不能用全池总量达标替代逐节点内存/GPU和镜像兼容检查。

时效阈值也不同：对方默认6秒SUSPECT、15秒OFFLINE/资源过期，己方快照超过8秒被过滤。应分别记录采样周期、传输时间、资格TTL与UI刷新周期，用实测延迟配置阈值；不能只把TTL放宽就宣称达到≤5秒感知目标。

| 能力 | 己方现状 | 对方现状 | 下一轮建议 |
|---|---|---|---|
| 获取节点 | ResourceProvider.GET /nodes，数组 | GET /api/v1/nodes，items包装；POST /api/v1/compute-pool/candidates | 增加明确的来源适配；保留审批排除原因与原始采样时间 |
| 预留调用契约 | reserve(node,task,attempt/session,requirements,snapshot,lease) | 无reservations路由；候选查询不写占用 | 第一阶段不直接启用旧URL路径；新增资源资格模式与单调度器持久化准入，明确不支持全局租约 |
| 释放 | cleanup完成后release | 仅按执行投影状态算allocated | 先建立会话清理确认和占用状态，不能将业务成功/LOST直接解释成释放 |
| 最终选点与下发 | 自己的scheduler、session_execution、kube | 调度提交未配置 | 保留现有唯一执行链路 |
| 执行事件 | tasks/attempts/execution_sessions/events | execution-events；attempt为键 | 扩展scope/session_id或分离会话占用与分片明细，资源只计会话一次 |
| 全量同步 | 需要可恢复投影 | executions/snapshot无条件全替换 | 增加来源/完整性/水位与逐对象版本条件，不按task局部数据调用全量替换 |
| 前端资源API | 现有/api/nodes偏执行节点 | /api/v1/nodes偏物理资源 | BFF或适配路由区分物理资源与执行节点，页面提供关联，不让两个同名/nodes互相覆盖 |

建议修改位置（均未修改）：

- `app/resource_provider.py`：拆开只读资格与预留能力；加入上游数据适配、明确失败语义和专用HTTP客户端。
- `app/container_execution.py`：合并资源与K3s状态、逐节点错误隔离、保留来源与新鲜度。
- `app/session_execution.py`：会话粒度准入、复用、释放及未清理占用；避免外部投影反向挡住自有会话。
- `app/db.py`及新增绑定/同步模块：bindings、可靠事件发送记录、版本水位和重放游标；不挪用历史task/attempt ID。
- `web/src/`：以独立资源模块逐页接入，统一API/导航/样式，保持既有任务页面。
- 独立命名空间的资源服务/Agent模块：保存来源与固定版本，避免两个顶层`app`包导入冲突。

## 4. 事件与清理约定

| 己方情况 | 对方现有近似状态 | 集成要求 |
|---|---|---|
| 会话STARTING/模型加载 | STARTING | 会话占用已承诺；同会话分片不得再累计 |
| 会话READY且未处理分片 | 现协议无READY | 必须表达模型已驻留且资源占用，不能映射为空闲零占用 |
| 分片RUNNING | RUNNING | 分片状态是明细，不再额外分配一张GPU |
| 分片SUCCEEDED但会话继续 | SUCCEEDED | 只结束分片，保留会话资源 |
| 任务SUCCEEDED但cleanup未DONE | SUCCEEDED | 保留会话占用直到清理确认 |
| 取消CANCELED | CANCELLED | 明确拼写映射；取消请求与实际清理分开 |
| TIMED_OUT / UNKNOWN / STOPPING | 缺少对应完整语义 | 增加原因与清理状态，不能只压成FAILED |
| 节点失联/LOST | LOST且现实现不计占用 | 未核实进程终止前保留承诺，隔离节点后继续核对 |
| 会话CLOSED且cleanup=DONE | 无独立字段 | 可释放占用，保留业务终态及来源 |

可靠同步建议使用持久化发送记录、单调事件版本、重试与幂等确认。快照必须声明完整性及截止水位；不得让较旧快照回滚较新事件，也不得以未完整获取到的数据生成空全量快照。调度数据库是业务事实源，资源数据库仅保存投影。

## 5. 资格准入与运行保护

先做“观测对照模式”：资源只展示、记录与现有调度结果的差异，尚不决定正式选点。确认数据稳定后，再启用资源资格作为新会话/新片段的过滤条件；源不可用时按明确策略停止依赖它的新分配，已有会话由自身协议管理。

暂停调度建议采用“当前已领取片段按既有取消/完成策略处理，后续新片段和新会话不再派入”的口径，管理员强制停止通过任务/会话取消链路执行。该口径须在UI说明并实测。

资源管理写接口目前无节点凭据机制。原生部署前分开管理员操作和Agent上报权限，复用项目现有证书/令牌配置方式，凭据不进入Git和网页。隔离核验不开放监听端口。

只读阶段若无需预留能力，就不返回虚假的reservation_id；多任务源共享资源前必须补原子比较/占用、幂等键、冲突、租约、续租、释放、超时与重启恢复测试。
