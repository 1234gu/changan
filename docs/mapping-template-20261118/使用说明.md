# 视频 / 航拍建图双模板使用说明

## 1. 进入平台

本机管理端：`http://127.0.0.1:8310/`。API文档：`http://127.0.0.1:8310/docs`。源码不在Mac开发；Mac运行根目录为 `/Users/eins/code/changanPlatform`。

在“运行总览”或“任务中心”点击 **新建任务**，在 **任务类型** 下拉框中选择：

- **视频分析**：原上传视频/示例视频、分片、采样率、阈值、节点和执行可视化照常使用。
- **航拍建图**：显示独立照片数据集、上传照片包、成果预设、分辨率和CPU并行度。不会保留或传入视频的sample_fps、confidence、segment_seconds等字段。
- 当前没有“通用任务”选项，不能从此页面提交任意镜像。

## 2. 推荐演示操作

1. 先查看已完成任务 **Brighton · 网页标准建图**，核对18/18、正射预览、实际Thor2和7种产物，不需要再次计算即可展示成果。
2. 新建任务→航拍建图→选择已经上传的 `drone_dataset_brighton_beach-master.zip`（18张）→标准→10 cm/px→4核→自动选择或thor2→创建并运行。
3. 在详情页看实际阶段；配准/稠密阶段可能持续较长，不提供臆造进度百分比。成功前不显示为已完成成果。
4. 成功后查看正射预览、配准数、尺寸、坐标系、点数，下载GeoTIFF/DSM/LAZ/PDF等。展开“镜像、Pod与调度依据”可核对固定镜像与实际执行身份。
5. 选择 `odm_data_aukerman-master (2).zip`（77张）与快速预设可演示另一套输入。快速档不是标准档的同质量捷径，不生成必需稠密点云和DSM。
6. 切回视频分析，原有上传与运行流程保持；在任务中心可同时找到两类任务。当前性能对比页只比较视频任务，不拿建图与视频算加速比。

本机原始ZIP仍在原位置。上传后平台保存独立受管副本及输入清单，重复上传会得到不同数据集ID；可优先复用数据集下拉框已有项。

## 3. 自备照片

建议ZIP内为 `images/*.JPG`，3～500张，保留EXIF和GPS；相邻航拍有足够重叠、避免只有无定位截图。单图≤64MiB，ZIP≤2GiB，总展开≤4GiB。照片名仅使用字母数字、下划线、连字符和点，长度≤120字符，包内仅有一个明确照片目录。

文件数合规与JPEG头通过只代表输入容器符合约定，不保证摄影测量能配准。无有效重建/地理参考/必需输出将失败，不会补造坐标或用样例产物顶替。首版不会把附带GCP或参考地图自动当作输入处理；不要以为把文件放进ZIP就启用了额外能力。

## 4. API约定与示例

上传（已有数据无需从网上下载）：

```bash
curl -f -F 'file=@/absolute/path/photos.zip' http://127.0.0.1:8310/api/datasets
curl -f http://127.0.0.1:8310/api/datasets
curl -f http://127.0.0.1:8310/api/applications
```

创建（使用上传返回的dataset_id，支持 `Idempotency-Key`）：

```json
{
  "workflow_id": "aerial-mapping-odx",
  "name": "航拍照片标准建图",
  "source": "dataset_替换为真实ID",
  "preset": "standard",
  "resolution_cm": 10,
  "concurrency": 4,
  "node_ids": []
}
```

`POST /api/tasks`；`GET /api/tasks/{id}`、`GET /api/tasks/{id}/events`、`POST /api/tasks/{id}/cancel`、`POST /api/tasks/{id}/rerun`、`GET /api/tasks/{id}/export` 共用。成功结果 `result.artifacts` 每项含 `name,bytes,sha256,url`；下载后可自行计算SHA256。启用管理API密钥的部署应携带 `X-API-Key`，不要把内部attempt令牌用于管理接口。

## 5. 取消、重跑、异常

- 运行中点“取消任务”，父任务可先变为CANCELED，但旧Pod必须终止、Job和Secret被清理后才释放节点。等待清理期间不要人工强行解除占用。
- “重新运行”创建新任务和独立工作目录；不覆盖原结果，不从检查点继续。
- “无可行节点”：展开调度依据看资源池资格、ARM64、内存、CPU、临时盘预算及占用；不是换成视频模型就能解决。Thor1当前Agent未向此Mac资源池持续上报，不应固定它演示。
- “K3s准入”：检查命名空间Quota以及Pod事件。三Thor部署需在基础 `deploy/rbac.yaml` 后应用 `deploy/thor-workload-quota.yaml`；只重新应用基础文件会把配额改回视频旧值。修改配额属于管理员职责，不通过用户随意调大任务参数绕过。
- 失败详情及引擎报告用于排查照片质量和引擎错误；缺失产物不会计成功。清理后的失败任务不保留整个重建工作盘，只有平台已经持久化的证据；成功任务保留引擎JSON/PDF报告，不保存所有大型中间数据。

## 6. 启停与回退

沿用本机项目环境与已授权的登录用户会话。Mac重启后API/网关仍需手工启动；后台启动方式、网络权限与合盖边界未在此轮改造。

```bash
source /opt/homebrew/Caskroom/miniforge/base/etc/profile.d/conda.sh
conda activate changan-platform
export CHANGAN_SKIP_REDIS=1
python /Users/eins/code/changanPlatform/current/scripts/manage.py start
```

服务日志：`/Users/eins/code/changanPlatform/logs/api.log`、`container-gateway.log`。镜像由Mac TLS仓库提供，必须保持Thor能够访问本机局域网地址。

升级/回退先确认无在途任务、无待清理尝试与会话，停止API/网关，切换 `current` 到已核验release，再启动；不要就地修改发布文件。原视频版 `releases/20261115-37de4c3` 与本轮发布前配置、两库备份均保留。**不能直接恢复旧SQLite覆盖本轮新任务与成果**；需要数据回退时先备份增量并单独核对。建图新增表/列未删除视频历史数据。
