# 0.9.0 同图多节点协同建图与进程可视化

2026-11-18；在0.8.0双模板基础上开发，不引入WebODM前端、NodeODX或另一套调度器。用户看到的是同一个建图任务、一套源照片和一份融合成果，不是多个独立建图任务。业务代码在服务器开发、测试、构建；Mac使用原生管理面与OCI仓库，Thor承担实际计算。

## 实现边界

| 工作单元 | 计算与约束 | 向下游交付 |
|---|---|---|
| 准备 | Thor读取源照片与元数据，调用固定版OpenSfM空间聚类、增加米制重叠；检查原始照片覆盖、分组不重复、至少3张共同照片的连通关系 | 分组清单、父工程元数据和每个子模型独立种子归档 |
| 稀疏重建（并行） | 各子模型在不同Thor运行特征、匹配、轨迹与稀疏重建；保留OpenSfM图像路径清单，不回传全量特征缓存 | 相机、参考系、照片清单、轨迹、稀疏结果 |
| 统一对齐 | 仅所有必要稀疏结果成功后启动；调用ODX的全局对齐，缺失子模型对齐文件、配准照片图不连通均失败 | 每个子模型单独的对齐结果 |
| 地理成果（并行） | 每个子模型叠加自己的原照片种子和已对齐的重建，再生成地理成果。快速模式不做标准档的稠密重建 | 带切线、羽化的正射、中间地理文件，以及对应预设的点云/DSM |
| 融合与发布 | 汇聚所有预期子模型，禁止缺一块仍报成功。检查正射空间参考、标准档点云/DSM和全局唯一配准照片数。平台在进程成功与持久化摘要通过后才发布 | 正射、预览、相机位置、引擎记录、协同报告；标准档另有DSM和LAZ |

`N`个子模型生成`2N+3`个固定模板工作单元，各对应一个正常K3s Job。任务/单元/attempt身份与资源池准入沿用原平台；一个节点同任务同时仅执行一个单元。前置成功版本的文件名、字节数、SHA256与生产attempt持久化，下载端再次验证；对齐、融合均不依赖共享POSIX盘。文件缺失/摘要不符或前置版本失效时不发布。父任务取消后旧Pod不能继续更新业务结果。通用任务未对外开放。

**两个容易混淆的指标**：节点时间轴显示尝试的完整占用区间（可包含调度、传输、清理前的核验）；“跨节点同时计算”使用管理网关观察到的两轮计算起止事件求交，只统计至少两块不同实际节点同时执行计算阶段的墙钟时间。均不是加速比。
