# 同图协同建图 · 使用说明（平台0.9.0）

## 中期展示：建议从这里开始

1. Mac 打开 `http://127.0.0.1:8310/` → **任务中心** → 选择 **两节点标准建图 · Brighton · 全链路验证**（`task_b0b8a6727f1b4750`）。这是已经完成的实机任务，不需要再启动计算。直接打开 `http://127.0.0.1:8310/?page=detail&task=task_b0b8a6727f1b4750` 也可进入详情。
2. 看 **同图多节点协同进程**：两列子模型分别代表两轮并行计算；第一轮之后必须统一对齐，第二轮之后才允许融合。点任一单元可查前置依赖、真实节点、Pod 和调度依据。分组未完成时显示“等待生成工作单元”，不预设一条成功路线。
3. 看 **真实节点执行时间轴**：柱形跨度从尝试创建到结束，包括排队/传输。下方“跨节点同时计算”是不同实际节点的计算阶段起止事件交集，**不是**拿两段Pod存活时长相交。未结束时为截至当前的观测，最终以持久化事件为准。完成数是已通过校验的工作单元数，不是预计剩余时间。
4. 在 **地图成果** 查看正射预览、原始与配准照片数、尺寸、坐标系等。标准模式还可下载点云和DSM；协同任务下载`collaboration.json`（分组与覆盖报告），不借用某个子模型的 PDF 当作全图报告。

## 新建一次

**新建任务 → 任务类型「航拍建图」→ 照片数据集 → 执行模式「同图多节点协同」**。同一表单保留「单节点执行」。视频入口、镜像和原有模型复用不变；没有开放通用任务镜像/命令输入。

| 参数 | Brighton 重现实测 | Aukerman 联调参数 |
|---|---:|---:|
| 已登记输入 | Brighton 18张 | Aukerman 77张 |
| 成果预设 | 标准（正射/DSM/点云） | 快速（不要求稠密点云/DSM） |
| 每组目标照片数 | 9 | 40 |
| 空间重叠半径 | 25 m | 35 m |
| 最大同时参与节点 | 2 | 2 |
| 候选节点 | Thor2、Thor3 | Thor2、Thor3 |
| 每节点 CPU / 分辨率 / 最低配准率 | 4 / 10 cm/px / 0.90 | 相同 |

- 两套预设是成果质量选择，不是节点数量；同一输入同一预设才有比较基础。
- 「每组目标照片数」控制空间分组，**不是固定张数或板数**。同一照片可进入相邻组；两组各12张、共享6张，原始有效输入仍是18张。本版要求2～8个非重复子模型，输入含GPS，有连通的共同照片图。快速模式跳过稠密重建，不跳过统一对齐或覆盖验收。
- 不勾选节点由资源池自动选点。指定范围须至少有两块不同候选板。`max_nodes` 限制同时占用节点数；同一任务每节点同时仅一个阶段 Job。最后一个稀疏单元不得在只剩唯一已用节点时悄悄退化为单板成功。节点不合格时保持等待，到截止时限终止；不要绕过资源池准入。
- 失败时打开实际单元与事件；重叠不足、完全重复、配准率不达标、缺失必要产物均不发布为完整成果。参数调整后**新建运行**，不会修改历史。运行中取消走现有 K3s 回收流程，取消后不会再发布任何地图成果。

## API 示例

```json
{"workflow_id":"aerial-mapping-odx","name":"同图双节点演示","source":"dataset_f4653a052c984606","preset":"standard","execution_mode":"collaborative","max_nodes":2,"node_ids":["thor2","thor3"],"submodel_size":9,"split_overlap_m":25,"concurrency":4,"resolution_cm":10,"min_registered_ratio":0.9}
```

通过 `POST /api/tasks` 创建。`GET /api/tasks/{id}` 的 `work_units` 提供 `phase/submodel/dependencies`，`attempts` 提供真实节点及Pod；`GET /api/tasks/{id}/events?after=...` 返回增量事件。工作单元未满足依赖时不会创建 Job。任务重试使用新的 attempt；旧尝试的上传、回调与输入下载均被隔离。整个任务重新运行创建新的任务，不覆盖旧成果。

## 制品与运维

- 视频、单板建图、协同建图分别快照固定镜像摘要；在 `config/platform.env` 中通过 `CHANGAN_MAPPING_COLLAB_IMAGE` 指定支持阶段协议的镜像，缺失则拒绝提交协同任务，不把旧镜像当新镜像运行。Mac只管理、落盘与校验；摄影测量和融合均在Thor。
- 中间归档在 `data/tasks/<task>/<attempt>/` 持久化。网关只让已认领的Pod读取本工作单元明确依赖的成功版本；公共成果接口不提供下载中间归档。当前无自动中间产物保留期策略，应规划磁盘空间，运行期间切勿手工删除检查点。
- 当前版本不验收无缝纹理网格、GCP绝对精度或固定加速比。两节点是本次实测范围，不把三节点配置项当三板实测。

两个已验证展示记录：标准档`task_b0b8a6727f1b4750`和快速档`task_0136d2197acd4116`。如需独立复核，运行服务器仓库中的只读`verify_mapping_collaboration.py`，用`--api`指向有权访问的管理端、参数传入任务ID；它会逐一检查依赖时间顺序、两轮不同节点计算重叠及最终成果下载摘要。不能从单节点、回放或模拟运行得到本次双板验收结论。
